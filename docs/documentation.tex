\part{Business Proposition}

\section{Executive Summary}

Airports in expansion and reconstruction need digital tools that keep pace with changing layouts. Passengers---especially first-time visitors and international travellers---need immediate, intuitive guidance in Romanian, without downloading complex maps or asking staff for every turn.

\textbf{Iași Airport Digital Guide} is a mobile passenger assistant prototype that combines:

\begin{itemize}[noitemsep]
    \item \textbf{Discover mode} --- live camera view, gyroscopic direction overlay, and spoken guidance in Romanian;
    \item \textbf{FAQ assistant} --- instant answers about Iași Airport services, entirely on-device;
    \item \textbf{AR-ready architecture} --- Unity AR Foundation + native iOS audio plugins, prepared for floor-anchored navigation in the next iteration.
\end{itemize}

This hackathon MVP demonstrates a credible product direction for Aeroportul Internațional Iași: a single app that \emph{shows, tells, and guides}---not just a static brochure.

\section{The Problem}

\subsection{Context}

During terminal works and operational changes, passengers face:

\begin{itemize}
    \item unfamiliar walking routes and relocated services;
    \item outdated static signage;
    \item language barriers at information desks;
    \item stress when searching for check-in, security, food, or restrooms under time pressure.
\end{itemize}

Iași Airport is used here as a \textbf{conceptual case study}. The demo does not reproduce real indoor geometry; it proves how a digital guide could behave once connected to authorized airport data.

\subsection{Why a Multimodal Assistant}

Static PDF maps and generic GPS fail indoors because they cannot:

\begin{itemize}
    \item overlay directions in the passenger's field of view,
    \item speak guidance in the passenger's language hands-free,
    \item adapt when corridors or services move,
    \item answer contextual questions without staff intervention.
\end{itemize}

Our approach combines \textbf{visual} (camera + direction lines), \textbf{vocal} (Romanian voice clips), and \textbf{conversational} (FAQ) channels in one branded mobile experience.

\section{Our Solution}

\begin{solutionbox}
We built a \textbf{three-module passenger app} branded for Aeroportul Internațional Iași: \emph{Descoperă aeroportul} (Discover), \emph{Întrebări și răspunsuri} (FAQ), and \emph{Despre aplicație} (About). Discover mode delivers camera-based spatial hints and voice guidance; the FAQ module answers common airport questions offline; the codebase includes AR Foundation and graph navigation modules ready for production-scale indoor routing.
\end{solutionbox}

\subsection{Spatial \& Voice Guidance (Discover Mode)}

Discover mode is designed as a \textbf{multimodal orientation layer}:

\begin{enumerate}[label=\arabic*.]
    \item \textbf{Live camera preview} --- immediate situational awareness (WebCam / device rear camera).
    \item \textbf{Gyroscopic direction overlay} --- when facing forward, all three routes are shown; rotating left or right isolates Security or Ciambella lines.
    \item \textbf{Voice assistant} --- pre-recorded Romanian speech (Ioana voice profile) played through a native iOS \texttt{AVAudioPlayer} pipeline for reliable output alongside the camera session.
    \item \textbf{On-screen assistant bubble} --- synchronized text for accessibility and noisy environments.
\end{enumerate}

\begin{techbox}
The product narrative for stakeholders: \emph{``Point your phone, hear where to go, read it if you prefer.''} This is the core differentiator versus a static airport website or PDF map.
\end{techbox}

\subsection{AR Vision (Integrated Architecture)}

The codebase ships with \textbf{Unity AR Foundation} (ARKit on iOS, ARCore on Android) via \texttt{MobileARSessionBootstrap}. The hackathon demo prioritises a stable camera + overlay experience; the same project structure supports:

\begin{itemize}
    \item plane detection and floor-anchored arrow meshes (\texttt{DiscoverFloorArrowGuide});
    \item XR Origin lifecycle management;
    \item Editor tooling for iOS/Android AR configuration (\texttt{PlatformTools}, post-processors).
\end{itemize}

For jury and investor conversations, AR is presented as \textbf{Phase~2}: anchor direction arrows on detected floor planes while retaining the current voice + UI layer unchanged.

\subsection{Design Principles (Technical Jury)}

\begin{itemize}
    \item \textbf{Separation of concerns} --- UI bootstrap, discover logic, speech, chatbot, and navigation are isolated namespaces.
    \item \textbf{Offline-first} --- FAQ and voice clips require no backend; suitable for airport Wi-Fi constraints.
    \item \textbf{Native where Unity falls short} --- iOS audio session conflicts with camera are solved via a dedicated Objective-C++ plugin (\texttt{IosDiscoverAudio.mm}).
    \item \textbf{Progressive enhancement} --- Discover works with camera + UI; AR Foundation adds plane-anchored arrows when enabled.
    \item \textbf{Editor automation} --- platform setup, scene creation, and validation menus reduce human error in builds.
\end{itemize}

\section{Runtime Bootstrap \& Navigation}

\subsection{Entry Point}

\texttt{DemoAppBootstrap} (\texttt{DefaultExecutionOrder(-100)}) executes on scene load:

\begin{enumerate}[noitemsep]
    \item ensures \texttt{EventSystem} and \texttt{AudioListener} exist;
    \item creates \texttt{MobileARSessionBootstrap} (AR Foundation singleton);
    \item builds Canvas (1080$\times$1920 reference resolution);
    \item constructs four panels: Main Menu, Discover, FAQ, About;
    \item wires \texttt{AppController} panel references via reflection.
\end{enumerate}

\subsection{Panel State Machine}

\texttt{AppController} exposes \texttt{AppPanel}: \texttt{MainMenu}, \texttt{Discover}, \texttt{Faq}, \texttt{About}.

When leaving Discover, \texttt{AirportDiscoverController.OnDiscoverHidden()} stops the camera and resets the voice assistant---preventing resource leaks on mid-tier iPhones.

\subsection{Camera Pipeline (\texttt{SimpleCameraPreview})}

\begin{itemize}
    \item Requests \texttt{UserAuthorization.WebCam} on iOS/Android.
    \item Selects rear-facing \texttt{WebCamDevice} when available.
    \item Applies rotation and UV correction for portrait preview on \texttt{RawImage}.
    \item Runs independently of ARKit---stable preview for hackathon demos.
\end{itemize}

\subsection{Gyroscopic Direction Overlay (\texttt{DiscoverDirectionOverlay})}

On \texttt{Show()}, the overlay calibrates device yaw as ``forward''. Each frame:

\begin{itemize}
    \item $| \Delta yaw | \leq 38°$ $\rightarrow$ show all three lines (check-in, Security, Ciambella);
    \item rotate left ($-125°$ to $-38°$) $\rightarrow$ Security only;
    \item rotate right ($38°$ to $125°$) $\rightarrow$ Ciambella/toilets only;
    \item otherwise $\rightarrow$ check-in (forward) only.
\end{itemize}

Lines and hint cards are UI \texttt{Image} elements with programmatic layout in \texttt{DemoAppBootstrap.CreateDirectionLine}. Hint cards are \texttt{Button}s wired to \texttt{DiscoverVoiceAssistant}.

\subsection{Native iOS Audio (\texttt{IosDiscoverAudio.mm})}

Unity's built-in \texttt{AudioSource} conflicts with \texttt{WebCamTexture} audio sessions on iOS. Our plugin:

\begin{enumerate}[noitemsep]
    \item configures \texttt{AVAudioSessionCategoryPlayAndRecord} with \texttt{DefaultToSpeaker};
    \item loads WAV from \texttt{Application.streamingAssetsPath};
    \item plays via \texttt{AVAudioPlayer} on the main queue;
    \item logs \texttt{started=1} for Xcode diagnostics.
\end{enumerate}

C\# invokes native code with \texttt{[MarshalAs(UnmanagedType.LPUTF8Str)]} for IL2CPP-safe string marshaling.

\begin{techbox}
\textbf{Jury talking point:} We did not give up on voice---we engineered a native bridge when the game engine audio stack was incompatible with the camera pipeline. This is production-grade mobile problem solving.
\end{techbox}

\section{FAQ Module (\texttt{ChatbotManager})}

Fully on-device rule-based assistant:

\begin{itemize}
    \item 10 suggested question chips (instant tap-to-ask);
    \item free-text input with keyword normalization;
    \item auto-reset after 8 messages to prevent UI overflow;
    \item answers cover location, IATA (IAS), city transport, facilities, parking, check-in timing, Wi-Fi, routes, and app purpose;
    \item no LLM, no API keys, no latency---ideal for demo reliability.
\end{itemize}

Intent matching lives in \texttt{ChatbotManager.TryAnswer()} with bilingual keyword lists.

\section{Technical Differentiators for Jury}

\begin{techbox}
\begin{enumerate}[noitemsep]
    \item \textbf{Multimodal Discover stack} --- camera + gyro UI + native audio + text bubble (four output channels).
    \item \textbf{Native iOS plugin} --- custom \texttt{.mm} bridge solving AVAudioSession + IL2CPP marshaling.
    \item \textbf{AR Foundation ready} --- not a mockup video; real ARKit integration in codebase.
    \item \textbf{Graph pathfinding module} --- Dijkstra on editable JSON graph (staff reroute story).
    \item \textbf{Zero-API FAQ} --- reliable demo without network dependency.
    \item \textbf{Programmatic UI bootstrap} --- reproducible builds, easy team onboarding.
    \item \textbf{Editor DevOps} --- automated platform setup, plist post-processing, validators.
\end{enumerate}
\end{techbox}

\section{Glossary}

\begin{description}
    \item[Discover mode] Camera-based passenger orientation with gyro-filtered direction UI and voice guidance.
    \item[AR Foundation] Unity cross-platform AR framework (ARKit / ARCore).
    \item[StreamingAssets] Unity folder whose files are copied verbatim to the device bundle (\texttt{Data/Raw/} on iOS).
    \item[IL2CPP] Unity scripting backend used for iOS release builds; requires explicit UTF-8 marshaling to native plugins.
    \item[Demo Airport Layout] Fictional JSON graph for compliance-safe routing demos.
    \item[UiTheme] Central branding helper for consistent hackathon-quality UI.
\end{description}
